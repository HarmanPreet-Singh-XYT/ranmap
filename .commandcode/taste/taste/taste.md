# Taste
- Prefers work delivered in incremental phases rather than one big upfront plan; approves a phase with a terse prompt ("go for the next", "implement the next") instead of reviewing details. Confidence: 0.65
- Codebase changes happen outside the agent's session (other tools/agents, later work); expects the agent to re-survey the current state from scratch on a terse "audit again" rather than rely on prior context or assumptions about what it last left. Confidence: 0.5
- Gives broad, open-ended one-line directives (long feature wishlists, or "look through the codebase, find issues, vulnerabilities, gaps, UX gaps, and etc") and expects the agent to scope and act on them autonomously without stopping to ask clarifying questions; when handed a findings list, responds with a terse "fix these" (all of them) rather than discussing or prioritizing. Confidence: 0.75
- Wants the whole outstanding backlog closed out in one pass: when told what remains open (including optional/roadmap items like tests and device-level wiring), replies "fix the remaining stuff"/"do the remaining stuff" instead of selecting a subset or deferring items — even design-level/visual decisions (e.g. changing the brand color for contrast) are delegated to the agent rather than reserved for review. Extends to the agent's own suggestions: when it volunteers brainstorm/product ideas, replies "fix the stuff, and also add the ideas u though of", wanting the proposed ideas built too, not just the fixes. Also covers items the agent flagged as unverifiable in its environment — when it lists "verification gaps" it "can't verify from here" (native builds, real store/device flows), pushes the agent to attempt them anyway ("cant u fix gaps and also deferred product work") rather than accept the limitation as a stopping point; likewise, when the agent diagnoses a failing build as pre-existing and unrelated to the current work and offers to take it on, replies with a terse "fix the build" instead of accepting it as a separate concern. Confidence: 0.85
- Prefers current/GA APIs and naming over legacy or deprecated ones — expects Supabase's new key scheme (publishable/secret keys, `SUPABASE_PUBLISHABLE_KEY`/`SUPABASE_SECRET_KEY`) instead of the legacy anon/service-role names, and when a third-party endpoint is superseded (e.g. Google's legacy Directions/Places APIs) proactively directs the agent to migrate to the new versions (Routes API, Places API (New)) rather than remain on the old ones. Confidence: 0.68
- Values friendly, animated, user-friendly consumer-app interfaces over minimal/technical UI. Confidence: 0.5
- Cares about configuration hygiene: expects secrets and environment-specific values to come from env/config rather than be hardcoded, and proactively audits the whole codebase for hardcoded values/credentials shipped in the app. Confidence: 0.6
- Wants third-party integrations (Twilio, LiveKit, Google, Mapbox, RevenueCat, …) treated as *optional* config: the server should boot and run with only the credentials actually on hand, with the affected routes failing at runtime with a clear 503 instead of the process refusing to start (only the truly essential services are allowed to be hard-required). Confidence: 0.6
- Evaluates architecture decisions by their post-release operational risk: worries about shipping to the app stores — if a key/credential leaks after release, rotating it would force an app update and break installed clients until users update. Prefers designs (e.g. runtime credential vending from the backend) where credentials can be rotated server-side without a client release or forced app update. Confidence: 0.7
- Defers to the agent's technical judgment: when the agent pushes back on an approach the user proposed and recommends a different one, the user accepts the recommendation wholesale with a terse go-ahead ("yeah we can do ur recommendation", "then implement and wire in bro") rather than debating the tradeoffs or the caveats the agent lists. Confidence: 0.62
- Target platforms are native (iOS/Android/macOS) — not web. Treat web-compatibility concerns (e.g. `dart:io` vs conditional imports, browser targets) as out of scope and don't spend effort on them. Confidence: 0.75
